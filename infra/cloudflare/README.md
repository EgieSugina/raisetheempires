# Cloudflare caching for empireandallies.tsukimi.my

The site reaches Cloudflare through the `cloudflared` tunnel in
`infra/k8s/deployment.yaml`, so every request already passes the edge — but
until now nothing was cacheable there. Flask serves static files with
`Cache-Control: no-cache`, which makes each of the ~1,000 game assets
(~460 MB of SWF, PNG and MP3) revalidate against the origin pod on every
request, through the tunnel, for every player.

Two halves make caching work. Both are needed; the Cloudflare rules alone do
nothing while the origin says `no-cache`.

## 1. Origin headers (already in the code)

`empires-server.py` has a `CACHE_POLICY` table and an `after_request` hook that
stamps explicit headers:

| Path | `Cache-Control` | Why |
| --- | --- | --- |
| `/assets/`, `/nullassets/` | `public, max-age=31536000, immutable` | Original 2012 game art. Never changes. |
| `/js/ruffle/` | `public, max-age=31536000, immutable` | Pinned Ruffle build, content-hashed WASM. |
| `/js/`, `/css/` | `public, max-age=31536000, immutable` | Safe because the templates reference them through `asset_url()`. |
| `/img/` | `public, max-age=2592000` | UI art, 30 days. |
| `/files/.../ZGame.109338.swf` | `public, max-age=604800` | Patched per host at boot; 7 days. |
| `/gameSettings.xml`, `/en_US.xml`, `/questSettings.xml` | `public, max-age=3600` | Regenerated by the mod engine at boot. |
| `/changelog.txt` | `public, max-age=300` | |
| **everything else** | `no-store, no-cache, must-revalidate, private` | Session-bound: saves, gateway, admin, chat. |

Three guards keep player data out of any cache: only `GET`/`HEAD` with a 2xx/304
status is ever marked public, any response carrying `Set-Cookie` is forced to
`no-store`, and `AssetSkippingSessionInterface` (which predates this work)
already keeps the session cookie off asset paths entirely.

### Cache busting

`asset_url('js/empires.js')` renders `/js/empires.js?v=<mtime>`. Editing the
file changes its URL, so `immutable` is self-busting — no purge needed on
deploy, and no manual version bump. Use it for any new script or stylesheet
you add to a template:

```html
<script src="{{ asset_url('js/whatever.js') }}"></script>
```

Game art under `/assets/` and `/nullassets/` is not stamped. If a mod changes
one of those files, purge it (see below).

The stamp is the file's mtime. `COPY . .` in the Dockerfile preserves mtimes
from the build context, so a stamp changes only when the file does — but if a
build pipeline clones the repo fresh each time, every file gets the clone's
timestamp and all stamps change on every deploy. That is safe (never stale),
just a cold cache for the ~29 MB of template JS after each deploy; game art
under `/assets/` is unaffected either way.

## 2. Cloudflare cache rules

Cloudflare's defaults only cache a fixed list of file extensions and would
leave `/gameSettings.xml` and the extension-less routes uncached, so the rules
in `cache-rules.json` make the decision explicit:

1. **Bypass** — `/`, `/ruffle.html`, `/login.html`, `/admin*`, `/chat/*`,
   `/friends/*`, `/support/*`, `/socket.io*`, `flashservices/gateway.php`,
   `record_stats.php` and the save-mutating GET routes (`/seed/`, `/patch/`,
   `/unlock_quest/`, …).
2. **Cache, respecting origin TTL** — `/assets/`, `/nullassets/`, `/img/`,
   `/js/`, `/css/`, `/files/empire-s.assets.zgncdn.com/` and the settings XML.

Both rules are scoped to `http.host eq "empireandallies.tsukimi.my"` so nothing
else on the `tsukimi.my` zone is affected.

### Applying them

```bash
export CLOUDFLARE_API_TOKEN=...

./apply-cache-rules.py                        # dry run: prints what changes
./apply-cache-rules.py --apply                # write
./apply-cache-rules.py --apply --tiered-cache # write + Smart Tiered Cache
```

The zone's cache-rules phase holds every cache rule for `tsukimi.my` and a write
replaces the whole list, so the script reads the current rules first, replaces
only the ones it previously wrote (description prefix `empireandallies:`), keeps
any other site's rules untouched, and prints the full before/after in the dry
run. Review that output before passing `--apply`.

API token scopes on the `tsukimi.my` zone: *Zone Settings → Edit*,
*Cache Rules → Edit*, and *Cache Purge → Purge* for the purge flags.

### Smart Tiered Cache

Worth turning on (`--tiered-cache`). Without it every Cloudflare datacenter
that a player connects from pulls each asset through the tunnel independently;
with it they pull from one upper-tier datacenter, so the tunnel and the Flask
pods see roughly one request per asset instead of one per region. This is a
**zone-wide** setting — it affects every site on `tsukimi.my`, though it is
beneficial for essentially all of them.

### Doing it in the dashboard instead

Caching → Cache Rules → Create rule, for each rule in `cache-rules.json`:
paste the `expression` into the expression editor (Edit expression), then set
*Cache eligibility* to **Bypass cache** for the first rule, and for the second
**Eligible for cache** with both *Edge TTL* and *Browser TTL* set to
**Respect origin TTL**. Put the bypass rule above the cache rule.
Smart Tiered Cache lives under Caching → Tiered Cache.

## 3. Verify

```bash
./verify-cache.sh                        # production
./verify-cache.sh http://127.0.0.1:5005  # origin headers only, no CDN
```

Assets should report `cf-cache-status: HIT` with a public `Cache-Control`;
dynamic URLs must report `BYPASS` or `DYNAMIC` with `no-store`. A `HIT` on a
dynamic URL is a bug — one player's session would be served to another.

## 4. Purging

Deploys of template JS/CSS need no purge (the `?v=` stamp changes). Purge when
you change game art, the settings XML or the SWF:

```bash
./apply-cache-rules.py --purge /gameSettings.xml /nullassets/dict1.swf
./apply-cache-rules.py --purge-all        # everything on the hostname
```

## Optional extras

- **Cache Reserve** (paid add-on) backs the edge cache with R2. A good fit here:
  ~460 MB of large, rarely-changing assets that would otherwise be evicted
  between play sessions and re-pulled through the tunnel. Enable under
  Caching → Cache Reserve once the rules above are live.
- **Brotli / HTTP/3 / Early Hints** are zone-wide switches under Speed, left
  alone here because they affect every `tsukimi.my` site. The origin already
  runs `flask_compress`.

## What is deliberately not cached

`/flashservices/gateway.php` is the AMF endpoint the game talks to and is
`POST`-only, so it is never cacheable regardless; the bypass rule exists so a
future `GET` variant cannot slip through. `/record_stats.php` is a beacon the
game fires constantly, and `/socket.io` is the admin log websocket.
